# 平台比对与实测记录

> 记录本 skill 对百度开发者平台（dev2.baidu.com）的比对结果与真实调用观测，用于区分「已验证」与「仅文档记载」。

## 2026-09-18 比对批次

### 一、接口地址比对：47 / 47 一致

**方法**：逐个打开官方接口文档页，抓取页面上的「请求地址」，与 `scripts/api.ts` 注册表的 `endpoint` 逐条比对。

- 覆盖范围：文档标题在官方目录中唯一、可直接定位的 47 个 action。
- 结果：**47 条全部一致，0 条不一致**。
- 未覆盖：12 个 action 的官方页标题在目录中重复（如「查询计划」同时存在于电商/搜索/信息流），需人工指定层级，本轮未比对；另有 4 个 OAuth action 统一走 `oauth-token-flow.md`。

### 二、错误码比对：33 个被引用码全部有出处

**方法**：抓取官方「错误代码」页全文（`附录 > 错误代码`，nodeId 166，当前 849 条），把 SKILL.md 与各文档引用的每个 `baiduCode` 逐条查表。

| 分类 | 数量 | 说明 |
|---|---|---|
| 官方码表可查 | 26 | 中文注释与本 skill 的「含义」列一致 |
| 网关级实测码 | 7 | `81020` / `87091` / `90180009000` 等**不在官方码表中**，来自真实响应观测 |

比对中发现并修正的一处偏差：`9015` 的官方原文是「请求的对象中包含空元素」，本 skill 原先写作"参数异常或为空"，已改为官方表述并补充实测覆盖情况。

### 四、只读接口受控故障注入（真实调用观测）

**方法**：对 9 个只读接口分别发送「空 body」「字段名拼错」「不存在的 ID」，记录百度真实返回。**全程只读，无任何写操作。**

产出 4 条此前未掌握的真实行为：

| 观测 | 含义 |
|---|---|
| `9011519 Request field is invalid` | 字段类错误的真实码（空 body / 字段名拼错）；此前误用 `99912` 描述此类场景 |
| `9015` / `9013` 的真实触发条件 | `9013` 实测是"缺参数被服务端当系统错误抛出"，不是单纯的服务端故障 |

| `segment-get` / `fc-transtrace-list-get` 静默忽略未知字段 | `status=0` 不代表筛选条件生效 |

### 五、尚未验证（明确标注，不冒充已验证）

1. **写操作权限码的触发实测**：`90121` / `901301` / `901431` 等只做了「按动作精确映射」并与官方码表核对，**未实测触发**。安全验证方式：用明确不存在的对象 ID + `confirmWrite` 调用一次，服务端会在对象/权限校验处返回，不会改动真实数据。
2. **剩余 12 个 action 的官方页比对**：因官方目录标题重复，需人工指定层级后补测。
3. **全部 44 个写操作的参数约束**：仅核对了上表 6 个接口，其余沿用官方页抓取内容但未逐条复核。

## 复现方式

接口存活探测方式（无需凭据，网关先校验 URL 再校验鉴权）：

```bash
curl -s -X POST 'https://api.baidu.com/json/sms/service/<Service>/<method>' \
  -H 'Content-Type: application/json;charset=utf-8' \
  -d '{"header":{"userName":"probe","accessToken":"invalid"},"body":{}}'
```

判据：`87091` = URL 不存在；`81020` = 存在但鉴权失败。

平台比对需要浏览器与登录态，核心步骤是「打开官方页 → 抓请求地址 / 错误码表 → 与注册表和文档逐条 diff」。
